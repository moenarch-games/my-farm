# Agent Instructions

My Farm is a local farming sim prototype. Domain context: `docs/agents/domain.md`.

Decision Atlas: `docs/decisions/atlas.md` is the one canonical nested-list Markdown source for what the product should be. Its semantic leaf entries are only **Decisions** and **Questions**; navigation branches are structure, not another entry type. Before making a consequential product choice, retrieve the relevant Atlas entries: follow Decisions, and ask the owner one unanswered Question at a time only when it materially affects the current task. Record a newly discovered consequential fork as a Question instead of deciding silently. Answering or changing intent appends a new linked Decision (`Answers X.Y` / `Supersedes X.Y`); never renumber, reorder, remove, reuse or silently replace an earlier entry. Do not introduce parallel categories such as constraints or deferred decisions. Update linked issues for implementation/acceptance, but do not create a parallel decisions database or mark unverified gameplay as implemented.

Some Decisions now have nested implementation-evidence checkboxes. Before planning work on one of those Decisions, inspect the **source entry and its checklist** even when `daq` has retrieved the decision: the current read-only index does not project child task-list lines. A checked box means only its narrowly cited capability is implemented/verified; an unchecked box names missing implementation or evidence. Neither a checked prerequisite nor an open broad parent PRD determines whether the complete user journey has passed. Reuse existing authoritative Rust code and independently verified Pages evidence before opening a new implementation issue or re-asking an already settled product choice.
